# Shinsegae_HideSeek

mmWave 센서로 관객이 가까워지면 캐릭터들이 숨고, 멀어지면 다시 놀이로 돌아오는 숨바꼭질 체험(로컬 PC 하드웨어 체험 앱, 시퀀스 영상 기반 연출)입니다.

현재(2026-10-23)는 **세로 9:16 실제 시퀀스 영상 + 유화 후처리 + 실센서(mmWave) 로컬 서버 직접 연결** 단계입니다. 제공된 원본 영상(HideSeek_Seq_1021) 7개 중 6개(SC3 너구리 빼꼼은 미사용)와 복귀 영상의 역방향 파생 영상 1개를 근접 판정에 따라 재생하고, 그 위에 ThrowSnow와 같은 유화 필터를 입힙니다. 로컬 서버(`npm start`)가 ESP32 센서 보드의 USB 시리얼을 **직접** 읽습니다 — 기존 Python 센서 툴·WebSocket 8765는 필요 없습니다. 개발 패널에서 모의 입력으로 바꿀 수도 있습니다. 실센서 경로는 기본 COM4 수신과 브라우저 연결까지 확인했습니다(자세한 결과는 최신 로그). 현장 수치 조정·장시간 동작·센서 설정 명령의 실기기 적용은 미검증입니다.

## 실행

- 필요: Node.js 24 이상, WebGL2를 쓸 수 있는 브라우저(Chrome 권장). 실센서는 ESP32 센서 보드(현재 CH343 USB-UART, 예: COM4)와 기존 펌웨어(USB 시리얼 115200 JSON 줄).

```sh
npm ci           # three 0.186.1, serialport 13.0.0 설치(Windows는 동봉된 미리 빌드 바이너리 사용)
npm start        # http://127.0.0.1:8091/display/ (루트 / 는 이 주소로 이동) — 센서 보드 후보가 1개면 자동으로 연결
npm test         # 근접 판정·시퀀스 상태·재생기 되감기·미디어 서버·실센서 연결(가짜 장치) 테스트(node:test)
```

- **기존 Python 센서 툴(`sensor_tool.bat`)을 먼저 닫으세요.** 같은 COM 포트를 한 프로그램만 열 수 있습니다. 툴이 포트를 쥐고 있으면 패널에 "다른 프로그램이 사용 중" 안내가 나오고 3초마다 다시 시도합니다(이 서버는 다른 프로그램을 종료하지 않습니다).

- 포트 변경: `PORT=8092 npm start` (PowerShell: `$env:PORT=8092; npm start`). `PORT=0`이면 빈 포트를 자동으로 고르고 실제 주소를 출력합니다.
- 서버는 `127.0.0.1`에서만 열리며 `public/`, three 고정 파일 2개, 아래 미디어 allowlist, 센서 API(`/api/sensor/…`)만 제공합니다.
- 패널에서 바꾼 앱 판정 설정·센서 희망값은 `.local/hideseek-settings.json`(Git 제외)에 저장되어 새로고침·서버 재시작 뒤에도 유지됩니다.

## 실센서 연결

```text
SEN0610(C4001) → UART 9600 → ESP32-S3 펌웨어(변경 없음) → USB 115200 JSON 줄 → 로컬 서버(serialport) → 같은 주소 SSE → 표시 페이지(안정화 → 근접 판정)
```

- **포트:** 시작할 때 알려진 센서 보드 USB 칩(CH34x·CP210x·Espressif)이 정확히 1개면 그것을 고르고 엽니다. 0개·여러 개면 열지 않고, 패널의 COM 목록에서 골라 `연결`합니다(목록에 있는 포트만). `해제`는 자동 재연결도 멈춥니다. 끊기면 3초마다 다시 연결합니다.
- **보드 재부팅 방지:** DTR/RTS를 쓰지 않도록(`hupcl: false`, `rtscts: false`) 엽니다. 연결할 때 보드에 아무 명령도 보내지 않습니다. 다만 포트를 여는 순간의 신호는 OS·USB 드라이버에 달려 있어 모든 환경에서 재부팅이 없다고 보장하지는 않습니다(패널의 '보드 부팅 메시지' 수로 확인).
- **안전 정지:** 연결 끊김·센서 설정 명령 처리 중·거리 모드가 아님·거리 데이터 1.2초 무수신(heartbeat만 오는 경우 포함)은 안전 정지(H)입니다. `n=0`(감지 없음)은 원거리(기본 놀이)로 보며 그때의 거리 0은 쓰지 않습니다.
- **입력 안정화(임시값, 패널에서 조절):** 최근 감지 거리 3개 중앙값(단발 튐 완화), 감지 중 `n=0`이 350 ms 안에 끝나면 직전 거리 유지. 계속 틀린 거리는 고치지 못합니다.
- **센서 자체 설정:** 패널의 `센서에 보내기`를 눌렀을 때만 펌웨어 고정 명령(`cmd setRange`·`cmd setThrFactor`·`cmd setMicroMotion`·`mode 1`)을 차례로 보냅니다. 펌웨어의 `cmd applied`는 **보드가 처리를 마쳤다는 응답일 뿐 센서 실제 적용 확인이 아닙니다.** 현재 펌웨어는 설정을 읽어 오는 명령이 없어 센서의 실제 설정은 알 수 없습니다. 원문 명령·공장 초기화·재부팅·펌웨어 업로드는 기존 Python 툴의 몫입니다.

## 영상·이미지 경로

원본 영상 7개(그중 SC3는 재생하지 않는 보존 자료), 파생 영상 1개, 안전 정지 이미지 1개는 **저장소에 포함**되어 있습니다(사용자 결정, 2026-10-21 — 프로젝트·원본 폴더 경로가 바뀌어도 그대로 실행되도록). 원본 7개와 이미지는 변환 없이 복사했습니다. `SC4_Return_To_Play_Reverse.mp4`는 SC4 원본 프레임을 역순으로 인코딩한 **파생 영상**입니다(사용자 요청 — 복귀 도중 다가오면 같은 자세에서 되돌아 숨기, 재현 명령은 [2026-10-21-06 로그](docs/logs/2026-10-21-06-reverse-return.md)). 실행 중에는 ffmpeg가 필요 없습니다. 서버가 고정 목록만 `/media/...` 주소로 제공합니다.

| 환경 변수 | 기본 경로(프로젝트 기준) | 쓰는 파일 |
|---|---|---|
| `SEQ_DIR` | `public/display/assets/seq/` | `SC0A_Pat`·`SC0B_Roll`·`SC0C_Playful`·`SC1_Notice`·`SC2_Duck`·`SC4_Return_To_Play` `.mp4` + 파생 `SC4_Return_To_Play_Reverse.mp4` (실행 7개). `SC3_Hidden_Clue.mp4`는 원본 보존용 미사용 자료(재생하지 않음) |
| `POSE_DIR` | `public/display/assets/pose/` | `H_Hidden.png`(안전 정지 화면) |

- 기본 경로는 `server/media.js` 파일 위치 기준이라 실행 위치(cwd)와 무관합니다.
- 다른 폴더의 영상을 시험할 때만 `SEQ_DIR=... POSE_DIR=... npm start`로 덮어씁니다. **그 폴더에도 `SC4_Return_To_Play_Reverse.mp4`가 있어야 합니다** — 원본 7개만 있는 폴더(예: 원본 출처 폴더)를 가리키면 복귀 도중 다시 숨기가 불러오기 오류 → 안전 정지(H) → 재시도가 됩니다(서 있는 SC2로 대신하지 않음). 원본이 바뀌면 로그의 명령으로 파생 영상도 다시 만듭니다. 상대 경로는 **실행 cwd 기준**으로 풉니다. 폴더가 없으면 시작 때 경고를 출력하고 해당 주소는 404입니다.
- 출처(원본 위치, 참고용): 영상 `D:/2026-09_ShinsegaeChristmas/007_Assets/HideSeek_Seq_1021`, 정지 이미지 `D:/2026-09_ShinsegaeChristmas/007_Assets/Hide_Seek/HideSeek_Snowman_Play_v02/01_Masters/H_Hidden.png`. 원본이 바뀌면 다시 복사해 커밋합니다.

## 화면과 조작

운영 화면은 9:16 무대만 보입니다(창 비율이 달라도 늘리지 않고 맞춤, 남는 곳은 검정 — 센서 상태 같은 기술 표시는 무대에 그리지 않음). 개발 패널은 기본으로 숨어 있고, `D` 키나 주소 `?debug=1`로 엽니다. 패널은 무대 옆 칸에 열려 무대를 덮지 않습니다.

개발 패널(위에서부터): **입력 선택**(실센서 / 모의 입력, 시작은 실센서) · **센서 연결**(COM 목록·새로고침·연결·해제, 연결 상태·오류, 원본 거리·안정화 거리·감지·속도/에너지·마지막 거리 수신 경과·보고 모드·heartbeat·보드 부팅 메시지) · **앱 판정 설정**(숨기 경계·눈치챔/원거리 경계·이탈 여유·접근/후퇴 유지 시간·중앙값 창 1/3/5·감지 누락 유예 → `적용`: 검증·저장에 성공해야 판정에 반영, 판정은 잠시 안전 정지 후 다시 시작) · **센서 자체 설정**(감지 최소/최대 거리·감도 임계 1~99·미세 움직임·mode 1 → `센서에 보내기`, 희망값·최근 전송 기록·실제 설정(알 수 없음) 구분) · 모의 입력 · 화면 · 진단.

| 조작 | 동작 |
|---|---|
| 패널 `실센서`/`모의 입력` | 판정 입력을 바꿈(바꿀 때 판정·안정화를 초기화 → 안전 정지에서 다시 판정) |
| `가까이`/`중간`/`멀리` 버튼, `N`/`M`/`F` 키(0.4 m / 0.9 m / 1.6 m) — **모의 입력일 때만** | 거리를 바꾸고 입력 상태를 정상 감지로 돌림 |
| 거리 슬라이더 | 거리 값만 바꿈(감지 없음·입력 오류 상태는 그대로 — 그동안 거리는 전송되지 않음) |
| `감지 없음` | 대상이 없는 정상 샘플 → 원거리와 같이 기본 놀이 |
| `입력 오류` / `전송 중단` | 오류 샘플 / 샘플 끊김(1.2초 뒤 stale) → 안전 정지(H 화면) |
| `정상 입력 재개` | 정상 감지로 돌리고 전송 재개 |
| `O` 키, 패널 `유화 필터` | 유화 후처리 켬·끔(실패 후 다시 켜면 새로 시험) |
| 패널 `원본 비교` | 화면 왼쪽 절반을 필터 없는 원본으로 |
| `D` 키 | 개발 패널 표시 전환 |

거리 구간은 기획값(근거리 0.6 m 안, 중간 0.6~1.2 m, 원거리 1.2 m 밖)이고, 노이즈 여유·유지 시간·안정화·timeout·섞기(150 ms)·클립별 재생 구간(in/out)·자세 연결 구간(cues)은 **임시값**입니다. 기본값은 모두 `public/display/config/settings.js` 한 곳에 있고, 경계·유지 시간·안정화는 패널에서 바꾼 저장값(`.local/`)이 우선합니다.

연출 규칙(사용자 요청·정정 2026-10-21): 거리가 바뀌어도 고정 시간으로 자르지 않고, 지금 영상이 원본에서 미리 확인한 **연결 가능한 자세 구간**에 실제로 들어왔을 때 다음 영상으로 바꿉니다(구간이 없으면 그 영상 끝에서). 그래서 반응은 영상 위치에 따라 짧을 수도, 수 초 걸릴 수도 있습니다. 숨는 동작은 마치고, 입력 오류·끊김은 즉시 안전 정지합니다. 다시 나오는 도중 다가오면 그 자세에서 거꾸로 되돌아 숨고, 되돌아 숨는 도중 멀어지면 그 자세에서 다시 나옵니다(복귀 영상 정/역방향, 섞지 않음). 원본 영상 파일은 그대로 두고 클립별 재생 구간(in/out)으로 앞뒤의 같은 자세 유지를 줄이며, 영상 경계는 150 ms 섞습니다. 처음 숨을 때는 놀라는 동작부터 보여 주고(SC2 처음부터), 다 숨은 뒤에는 아무 영상도 재생하지 않고 숨은 마지막 화면으로 기다리다 멀어지면 나옵니다(너구리 빼꼼 SC3은 사용자 요청으로 재생하지 않음). 상세는 [SYSTEM 6장](docs/SYSTEM.md#6-시퀀스-상태).
