# 기술 명세

기술 규칙을 담는다. 체험 기획·범위는 [PROJECT.md](PROJECT.md), 작업 경위와 인계는 [logs/](logs/)의 최신 로그를 따른다.

- 상태(2026-10-20): **1단계 모의 입력 프로토타입이 구현되어 있다.** 모의 입력 → 근접 판정 → 시퀀스 상태 → 더미 재생·화면이 실제로 연결되어 동작한다. 실제 센서 어댑터·로컬 브리지·최종 영상 재생은 **미구현**이다.
- 표기는 PROJECT와 같다: **확정** / **제안** / **가정** / **임시 선택** / **미정**. 수치는 모두 설정 한 곳(8장)의 **임시값**이며 실측값이 아니다.
- 확정된 것은 웹 기반, 시퀀스 기반 연출, mmWave 센서 사용, 관객이 가까워지면 숨고 멀어지면 등장하는 동작뿐이다. 이 문서의 나머지 규칙은 제안이거나 1단계 임시 선택이다.

## 1. 구성과 기술 선택

- 단일 PC에서 로컬 정적 서버와 표시 페이지(브라우저)를 함께 실행한다. — 1단계 구현
- Node.js 24, 빌드 없는 ES module, 외부 런타임 의존성 없음(`package.json`에 dependencies 없음). — 1단계 임시 선택
- 서버(`server/server.js`): Node 내장 `http`. — 1단계 구현
  - `127.0.0.1`에만 bind. 포트는 `PORT` 환경 변수(기본 8091, `0`이면 빈 포트 자동 선택). 시작 시 실제 주소를 출력한다.
  - 잘못된 `PORT`, 사용 중 포트, 권한 오류는 한국어 문구를 출력하고 종료 코드 1로 끝낸다.
  - `public/` 아래만 제공한다. GET/HEAD만 허용(그 외 405), `/`는 `/display/`로 302, 폴더 주소는 끝 `/`로 301 후 `index.html`. 디코딩 실패·NUL·역슬래시·`.`으로 시작하는 경로 조각(`..`, `.env`, `.git` 등)·`public/` 밖으로 풀리는 경로는 404. 확장자별 MIME, 없는 파일 404, `Cache-Control: no-store`(개발용).
- Three.js 사용 여부, 영상/이미지 시퀀스 선택, 로컬 브리지 필요 여부는 소스와 센서를 확인한 뒤 정한다. — 미정
- 브라우저가 mmWave 센서를 직접 읽을 수 있다고 가정하지 않는다. 센서 인터페이스(시리얼·USB·네트워크 등)가 정해진 뒤 브라우저 API로 가능한지, 로컬 브리지가 필요한지 정한다. — 미정

## 2. 경계와 데이터 흐름

```text
[모의 입력 어댑터 | (미구현) 센서 어댑터] → 공통 근접 샘플 → 근접 판정 → 시퀀스 상태 → 재생기·화면
                    (미구현, 선택) 로컬 브리지 ─┘
```

| 구성 요소 | 1단계 구현 | 맡는 일 | 맡지 않는 일 |
|---|---|---|---|
| 입력 어댑터 | `input/mock-input.js` | 선택된 거리·상태를 일정 간격의 공통 근접 샘플로 내보낸다. | 근접 판정, 연출 |
| 모의 조작부 | `input/mock-controls.js` | 슬라이더·버튼·단축키를 어댑터 호출로 바꾼다(개발용). | 판정·시퀀스 코어 직접 호출 |
| 근접 판정 | `core/proximity.js` | 샘플을 안정화된 `near`/`far`/`unknown`으로 바꾼다(5장). | 장치 형식, 재생 |
| 시퀀스 상태 | `core/sequence.js` | 판정과 재생 완료·오류로 상태를 바꾸고 재생 지시를 낸다(6장). | DOM, 키 이벤트, 원시 센서 패킷 |
| 재생기 | `scene/dummy-player.js` | 지시받은 클립을 재생하고 완료·오류를 재생 ID와 함께 알린다(7장). | 상태 결정 |
| 조립 | `main.js` | 위 모듈을 연결하고 주기 확인(tick)과 진단 갱신을 돌린다. | 판정·전환 규칙 |

- 근접 판정과 시퀀스 상태는 현재 시각 `nowMs`를 인자로 받는 순수 모듈이다(DOM·타이머 없음). 실제 센서 어댑터도 같은 샘플 규격으로 같은 경로를 타게 한다. — 1단계 구현
- 단축키·DOM 이벤트는 코어로 가지 않는다. 판정이 **바뀔 때만** 시퀀스 상태에 전달한다.

## 4. 공통 근접 샘플 — 1단계 구현

| 필드 | 의미 |
|---|---|
| `source` | 입력 출처(현재 `mock`, 이후 예: `mmwave`). 빈 문자열 불가 |
| `timestampMs` | 샘플을 받은 시각. 페이지 단조 시계 `performance.now()` 기준 ms, 0 이상 유한수 |
| `status` | `ok`(대상 감지, 거리 있음) / `no-target`(장치는 정상, 감지 대상 없음) / `error`(장치 오류·연결 끊김·형식 오류) |
| `distanceM` | `status`가 `ok`일 때만. 센서 기준 대상까지 거리, 0 이상 유한수, 미터 |

- 정상 무감지(`no-target`), 오류(`error`), 오래된 샘플(stale)을 구분한다. stale은 판정 단계가 정한다(5장).
- 여러 사람 감지 시 대표 거리 선택, 정지한 사람 감지 특성, 거리 대신 존재 여부·구역만 주는 장치 대응은 센서가 정해진 뒤 정한다. — 미정

## 5. 근접 판정 — 1단계 구현

출력은 `near` / `far` / `unknown` 중 하나다. 최초는 `unknown`.

- **구역:** 거리 ≤ `nearMaxM`이면 근거리, ≥ `farMinM`이면 원거리, 그 사이는 사이 구간(히스테리시스). `nearMaxM < farMinM`이 아니면 생성 시 오류.
- **연속 유지:** 근거리(원거리) 샘플이 샘플 시각 기준 `nearHoldMs`(`farHoldMs`) 이상 끊김 없이 이어져야 `near`(`far`)로 바뀐다. 유지 중 사이 구간·반대 구간·현재 판정과 같은 구간·`no-target`·거절된 샘플이 오면 후보가 끊기고 다음 샘플부터 새로 센다.
- **사이 구간:** 이전 판정(`unknown` 포함)을 유지한다.
- **신호 공백:** 후보 유지 중 샘플 간격이 `maxSampleGapMs`를 넘으면 공백을 유지 시간으로 세지 않고 새로 센다. 직전 정상 샘플과의 간격이 `staleMs`를 넘으면(주기 확인이 늦었어도) 먼저 `unknown`으로 바꾼 뒤 그 샘플부터 다시 판정한다.
- **샘플 거절:** 규격 위반(필드·상태·거리 형식, 음수 거리), 현재 시각보다 미래, `staleMs`보다 오래됨, 직전 정상 샘플보다 이른 시각(역행)은 판정에 쓰지 않는다. 진행 중 후보도 끊는다. 거절만 계속되면 stale이 된다. 최근 거절 사유는 진단에 보인다.
- **`no-target`:** 이전 안정 판정을 유지하고(시작 `unknown`이면 그대로) 진행 중 후보만 끊는다. `far`로 바꾸지 않는다. stale 시계는 갱신한다(장치는 살아 있음). — 임시 선택. `far`로 볼지는 센서 규격 확인 후 정한다(미정). 설정 항목으로는 아직 두지 않았다.
- **`error`·stale:** 즉시 `unknown`, 후보 초기화. 회복 후 유지 시간을 처음부터 다시 채워야 한다. stale은 주기 확인(`tick(nowMs)`)에서 마지막 정상 샘플 후 `staleMs` 초과 시 정한다.
- 판정이 바뀐 호출에서만 `changed: true`를 돌려준다. 같은 판정이 반복되면 시퀀스에 아무것도 알리지 않는다.

## 6. 시퀀스 상태

1단계 구현. 상태: `visible-idle` / `hiding` / `hidden-idle` / `revealing`. 시작은 `hidden-idle` + 판정 `unknown`(임시 선택). 처음 `far`가 안정되면 등장한다.

| 현재 상태 | 조건 | 다음 상태 |
|---|---|---|
| `visible-idle` | 판정 `near` | `hiding` (숨기 클립 시작) |
| `hiding` | 현재 재생 ID의 숨기 완료 | `hidden-idle` → 최신 판정 재평가 |
| `hidden-idle` | 판정 `far` (재생 오류 대기 중이 아닐 때) | `revealing` (등장 클립 시작) |
| `revealing` | 현재 재생 ID의 등장 완료 | `visible-idle` → 최신 판정 재평가 |
| 어느 상태든 | 판정 `unknown` | 진행 중 클립 취소 → `hidden-idle` (안전 대기) |
| `hiding`·`revealing` | 재생 오류 또는 timeout | 클립 취소 → `hidden-idle`, 재시도 대기 |

- **최신 판정 1개:** 판정은 항상 마지막 값 하나만 보관한다(큐 없음). 전환 중 바뀌면 덮어쓰고, 클립 완료 후 그 값으로 재평가한다. 예: 숨는 중 `far` → 다 숨은 뒤 `revealing`. 나오는 중 `near` → `far`로 되돌아오면 완료 후 추가 전환 없음.
- **반복 판정:** 같은 판정은 무시한다. 전환은 상태와 판정이 어긋날 때만 일어난다.
- **재생 ID:** 클립을 시작할 때마다 새 ID(1부터 증가). 완료·오류 알림은 현재 진행 중인 ID일 때만 받는다. 이전 재생의 늦은 알림, 중복 알림, 취소된 재생의 알림은 무시하고 진단에 횟수를 센다.
- **timeout:** 클립 시작 시각 + 클립 길이 + `playTimeoutMarginMs`를 넘기면 성공이 아니라 재생 오류(`timeout`)다. 재생기에 취소를 지시한다. 기한을 넘겨 도착한 완료도 timeout으로 처리한다. 백그라운드 탭 등으로 완료가 늦으면 timeout 후 재시도로 회복한다.
- **안전 대기(`unknown`):** 진행 중 클립 취소, 현재 재생 ID 무효화, 연출 없이 숨은 자세로 바로 둔다. `unknown`을 `far`로 처리하지 않는다. 정상 판정이 회복되면 새 ID로 다시 시작한다. 초기 초안에서 미정이던 "안전 대기 화면(마지막 정지 화면 / 숨은 상태)"은 1단계에서 **숨은 상태**로 임시 선택했다.
- **재생 오류 복구:** 오류 후 `playbackRetryDelayMs` 동안 새 전환을 시작하지 않고 숨은 상태로 대기한다. 대기가 끝나면 최신 판정으로 다시 판단한다(같은 `far`가 이어져도 새 ID로 다시 등장 시도). 오류가 계속되면 이 주기로 재시도한다.
- 모의 입력 "정상 입력 재개"는 입력만 회복시킨다. 판정·시퀀스는 위 정상 절차(유지 시간 충족 → 판정 변경 → 전환)로 회복한다.
- 등장 캐릭터가 여럿이 될지, 캐릭터마다 상태를 따로 둘지는 정하지 않았다. 현재는 한 캐릭터 기준이다. — 미정

## 7. 클립·레이어·재생

- 1단계 구현 — 더미 재생기(`scene/dummy-player.js`):
  - 계약: `play({ playId, clip, durationMs })`, `cancel(playId)`, `setPose('visible' | 'hidden')`, 결과 콜백 `onFinished(playId)` / `onError(playId, reason)`. 최종 영상 재생기는 같은 계약으로 바꿔 끼운다.
  - 클립 `hide`·`reveal`은 캐릭터 요소에 Web Animations API(`element.animate`)를 걸어 재생한다. 완료는 실제 `animation.finished`로만 알린다(타이머로 성공 처리하지 않음). 알림은 항상 비동기다.
  - 취소된 재생·교체된 재생의 결과는 알리지 않는다. Web Animations API가 없거나 실패하면 오류로 알린다.
  - 진단용 `snapshot(nowMs)`: 진행 중 재생과 마지막으로 끝난 재생(완료·취소·오류 시점)의 실제 `playState`·`pending`·`currentTime`과 시작 후 실제 경과 시간. 재생 계약의 일부는 아니다.
- 1단계 레이어(뒤 → 앞): 배경(하늘·눈·나무·뒤 언덕) / 캐릭터 / 전경(눈 언덕·덤불). 숨기는 캐릭터가 전경 언덕 뒤로 내려가고, 등장은 다시 올라온다. 보이는 대기는 살짝 들썩이고, 숨은 대기는 덤불이 흔들린다. 모두 CSS 도형의 **임시 연출**이며 최종 아트가 아니다.
- 최종 클립: 등장 / 대기 / 숨기 / 숨은 대기. 인접 클립·대기 사이의 접점(자세·위치·가림 상태)을 맞추는 원칙을 ThrowSnow에서 참고한다. — 제안
- fps, 파일 형식, 알파/크로마키, 클립 간 전환 방식, 불러오기 실패 시 대체 표시, 불러오기 취소·자원 정리(ThrowSnow `seq-media.js` 방식 참고)는 소스를 받아 본 뒤 정한다. — 미정

## 8. 설정과 진단

설정은 `public/display/config/settings.js` 한 곳에 있다. 아래 값은 모두 모의 입력 확인용 **임시값**이며 실제 센서·현장에서 정한 값이 아니다(3~4단계에서 실측으로 정함).

| 묶음 | 키 | 임시값 | 뜻 |
|---|---|---|---|
| proximity | `nearMaxM` | 1.2 m | 이하면 근거리 |
| | `farMinM` | 2.0 m | 이상이면 원거리 |
| | `nearHoldMs` | 350 ms | 근거리 연속 유지 시간 |
| | `farHoldMs` | 600 ms | 원거리 연속 유지 시간 |
| | `staleMs` | 1200 ms | 마지막 정상 샘플 후 이 시간 초과 시 stale |
| | `maxSampleGapMs` | 300 ms | 후보 유지 중 허용 샘플 간격 |
| sequence | `hideMs` | 700 ms | 숨기 연출 길이 |
| | `revealMs` | 900 ms | 등장 연출 길이 |
| | `playTimeoutMarginMs` | 1000 ms | 연출 길이에 더하는 timeout 여유 |
| | `playbackRetryDelayMs` | 3000 ms | 재생 오류 후 재시도까지 대기 |
| mock | `sampleIntervalMs` | 100 ms | 모의 샘플 발행 간격 |
| | `initialDistanceM` | 3.0 m | 시작 거리(원거리라 잠시 뒤 첫 등장) |
| | `nearPresetM` / `farPresetM` | 0.8 m / 3.0 m | 가까이·멀리 프리셋(N/F 키) |
| | `minDistanceM`~`maxDistanceM`, `stepM` | 0~5 m, 0.1 m | 슬라이더 범위 |
| display | `tickMs` | 100 ms | stale·timeout 확인과 진단 갱신 간격 |

- 진단 영역(1단계 구현): 입력 원본·전송 여부·보낸 샘플 수, 마지막 샘플(상태·거리), 마지막 샘플 경과(stale 표시), 근접 판정, 판정 후보와 유지 시간, 현재 단계, 현재 재생 ID·무시한 늦은 알림 수, 재생기 상태(진행 중·마지막으로 끝난 재생의 animation `playState`/`pending`, 진행 ms/클립 길이, 실제 경과 ms), 최근 오류(재생 오류·timeout·재시도까지 남은 시간·샘플 거절 사유). `D` 키나 제목으로 접고 편다.
- 1단계 개발 화면에서는 진단·모의 조작부를 기본으로 보인다. 운영 화면에서는 기본으로 숨기고 키나 URL 인자로 켜는 안을 제안한다(미구현). — 제안
- 단축키(N/F/D)는 물리 키(`event.code`) 기준이라 한글 입력 상태에서도 동작한다. 입력 칸·슬라이더·선택 상자에 초점이 있거나 조합 키·키 반복이면 무시한다.

## 9. 실행과 검증 구분

- 실행: `npm start`(`http://127.0.0.1:8091/display/`), 테스트: `npm test`(`node --test`, `test/`의 근접 판정·시퀀스 상태 시나리오). `npm install`은 필요 없다.
- 모의 입력으로 확인한 동작, 실제 센서로 확인한 동작, 현장에서 확인한 동작을 구분해 기록한다. 현재는 **모의 입력과 단위 테스트까지만** 있다. 센서·현장 수치와 장시간 동작은 미검증이다.
