# 기술 명세 (초안)

기술 규칙을 담는다. 체험 기획·범위는 [PROJECT.md](PROJECT.md), 작업 경위와 인계는 [logs/](logs/)의 최신 로그를 따른다.

- 상태(2026-10-20): **전부 미구현 초안이다.** 실행 코드·앱 폴더·프로젝트 의존성은 아직 없다.
- 표기는 PROJECT와 같다: **확정** / **제안** / **가정** / **미정**. 수치는 정하지 않았으며, 정할 때는 설정 한 곳(8장)에 둔다.
- 확정된 것은 웹 기반, 시퀀스 기반 연출, mmWave 센서 사용, 관객이 가까워지면 숨고 멀어지면 등장하는 동작뿐이다. 나머지는 제안이다.

---

## 1. 구성과 기술 선택

- 단일 운영 PC에서 로컬 웹 서버(정적 파일 제공)와 출력 페이지(브라우저)를 함께 실행한다. — 제안
- Node.js ES module, 빌드 단계 최소화(ThrowSnow와 같은 방향). — 제안, 이번 단계에서 설치하지 않음
- Three.js 사용 여부, 영상/이미지 시퀀스 선택, 로컬 브리지 필요 여부는 소스와 센서를 확인한 뒤 정한다. — 미정
- 브라우저가 mmWave 센서를 직접 읽을 수 있다고 가정하지 않는다. 센서 인터페이스(시리얼·USB·네트워크 등)가 정해진 뒤 브라우저 API로 가능한지, 로컬 브리지(서버가 장치를 읽어 페이지로 전달)가 필요한지 정한다. — 미정

## 2. 경계와 데이터 흐름 — 제안

```text
[센서 어댑터 | 모의 입력 어댑터] → 공통 근접 샘플 → 근접 판정 → 시퀀스 상태 → 재생·화면
        (선택) 로컬 브리지 ─┘
```

| 구성 요소 | 맡는 일 | 맡지 않는 일 |
|---|---|---|
| 입력 어댑터 | 장치 패킷·키 입력을 공통 근접 샘플(4장)로 바꾼다. 장치 연결 상태를 샘플 상태로 알린다. | 근접 판정, 연출 |
| 로컬 브리지 | 장치 프로토콜이 정해진 뒤 필요할 때만 둔다. 장치를 읽어 샘플을 페이지로 전달한다. | 판정, 연출 |
| 근접 판정 | 샘플을 안정화된 `near`/`far`/`unknown`으로 바꾼다(5장). | 장치 형식, 재생 |
| 시퀀스 상태(연출 코어) | 판정과 재생 완료 알림으로 상태를 바꾸고, 재생할 클립을 낸다(6장). | DOM, 렌더 라이브러리, 원시 센서 패킷, 키 이벤트 |
| 재생·화면 | 지시받은 클립을 레이어에 재생하고, 완료·오류를 재생 ID와 함께 알린다(7장). | 상태 결정 |

- 근접 판정과 시퀀스 상태는 시각(`nowMs`)을 인자로 받는 순수 모듈로 둔다. 모의 입력과 실제 센서가 같은 경로를 탄다. — 제안

## 3. 폴더 구성 — 제안 (실제 폴더 아님)

```text
server/                   로컬 정적 서버(필요 시 브리지)
shared/                   페이지·서버가 함께 쓰는 규격 — 필요한 경우만
public/display/
  input/                  센서·모의 입력 어댑터
  core/                   근접 판정, 시퀀스 상태 (DOM 없는 순수 모듈)
  scene/                  레이어 구성, 영상·이미지 재생
  config/                 센서 수치·미디어 설정 (한 곳)
  assets/                 실행용 최종 에셋 (관리 정책 미정)
test/                     순수 모듈 단위 테스트 — 필요할 때
```

- `docs/references/`의 참고 이미지는 실행용 에셋이 아니다. 실행에 쓰는 에셋은 `assets/`(또는 저장소 밖 경로)로 따로 관리한다. — 제안

## 4. 공통 근접 샘플 — 제안

| 필드 | 의미 |
|---|---|
| `source` | 입력 출처(예: `mock`, `mmwave`) |
| `timestampMs` | 샘플을 받은 시각. 페이지의 단조 시계(`performance.now()`) 기준 ms |
| `status` | `ok`(대상 감지, 거리 있음) / `no-target`(장치는 정상, 감지 대상 없음) / `error`(장치 오류·연결 끊김·형식 오류) |
| `distanceM` | `status`가 `ok`일 때만. 센서 기준 대상까지 거리, 미터 |

- **정상 무감지(`no-target`)와 끊김·오류(`error`)·오래된 샘플(stale)을 구분한다.** stale은 마지막 샘플 후 일정 시간(미정) 동안 새 샘플이 없을 때 판정 단계가 정한다.
- `no-target`을 "멀어짐"으로 볼지는 장치 규격(정지한 사람 감지, 감지 범위)을 확인하기 전에는 정하지 않는다. 그전까지 `no-target`은 판정을 바꾸지 않는다(이전 유효 판정 유지). 둘 중 무엇으로 할지는 설정 항목으로 둔다. — 미정
- 여러 사람 감지 시 대표 거리(가장 가까운 대상 등) 선택, 정지한 사람 감지 특성은 센서가 정해진 뒤 검토한다. — 미정
- 장치가 거리 대신 존재 여부·구역만 준다면 이 규격을 그때 조정한다. — 미정

## 5. 근접 판정 — 제안

출력은 `near` / `far` / `unknown` 중 하나다.

- `near`: 유효 거리가 근거리 임계값 이하로 근거리 유지 시간 동안 이어짐 → 관객이 가깝다.
- `far`: 유효 거리가 원거리 임계값 이상으로 원거리 유지 시간 동안 이어짐 → 관객이 멀다.
- `unknown`: 최초 상태, `error`, stale, 판정 근거 부족.

규칙:

- 근거리 임계값 < 원거리 임계값으로 서로 다르게 둔다(히스테리시스). 두 임계값 사이의 거리는 이전 유효 판정(`near`/`far`)을 유지한다. 수치는 미정.
- 일정 시간 유지를 확인한 뒤에만 판정을 바꾼다. 한두 샘플의 튐으로 바뀌지 않는다. 유지 시간은 미정.
- 최초 상태는 `unknown`이다. `unknown`에서 나오려면 위 조건을 새로 만족해야 한다.
- `error`·stale이면 `unknown`으로 바꾼다. 정상 샘플이 회복되면 처음부터 다시 판정한다.
- 판정이 **바뀔 때만** 시퀀스 상태에 알린다. 같은 판정이 반복돼도 아무 일도 일으키지 않는다.

## 6. 시퀀스 상태

상태: 제안.

최소 상태: `visible-idle` / `hiding` / `hidden-idle` / `revealing`.

| 현재 상태 | 조건 | 다음 상태 |
|---|---|---|
| `visible-idle` | 판정 `near` | `hiding` (숨기 클립 시작) |
| `hiding` | 숨기 클립 완료 | `hidden-idle` → 최신 판정 재평가 |
| `hidden-idle` | 판정 `far` | `revealing` (등장 클립 시작) |
| `revealing` | 등장 클립 완료 | `visible-idle` → 최신 판정 재평가 |

- **전환 중 반전:** `hiding`·`revealing` 도중 판정이 바뀌면 최신 판정 하나만 보관하고(이전 값은 덮어씀, 큐 없음), 진행 중 클립을 마친 뒤 재평가한다. 예: 숨는 중 `far`가 되면 다 숨은 뒤 `revealing`.
- **반복 근접:** `near`가 계속 들어와도 숨기 클립을 다시 시작하지 않는다. 전환은 상태와 판정이 어긋날 때만 일어난다.
- **완료 판정:** 클립을 시작할 때마다 재생 ID를 붙인다. 완료 알림은 실제 재생 완료이고 현재 재생 ID와 같을 때만 받는다. 이전 재생의 늦은 완료 알림은 무시한다.
- **타임아웃:** 완료가 예상 시간 안에 오지 않으면 성공 완료로 취급하지 않고 재생 오류로 처리한다. 예상 시간·여유는 미정.
- **오류·unknown:** 소스 오류·재생 오류·센서 단절(`unknown`)이면 새 전환을 시작하지 않고 안전 대기한다. 정상 신호와 소스가 회복되면 최신 판정으로 다시 판단한다. 안전 대기 중 보여 줄 화면(마지막 정지 화면, 숨은 상태 등)은 미정.
- **시작 상태:** `unknown`을 `far`로 오인해 저절로 등장하지 않도록 `hidden-idle`에서 시작하고 `far` 판정을 기다리는 안을 제안한다. 시작 시 캐릭터를 보일지는 미정(PROJECT 7장).
- 등장 캐릭터가 여럿이 될지, 캐릭터마다 상태를 따로 둘지는 정하지 않았다. 이 표는 한 캐릭터(또는 한 묶음) 기준이다. — 미정

## 7. 클립·레이어·미디어 — 제안

- 클립: 등장 / 대기 / 숨기 / 숨은 대기. 숨은 대기는 정지 화면이나 빈 레이어여도 된다.
- 레이어(뒤 → 앞): 배경 / 캐릭터 / 전경. 전경이 캐릭터를 가려 "숨는" 표현이 가능하게 둔다.
- 숨기는 보이는 대기 → 숨은 상태, 등장은 숨은 상태 → 보이는 대기로 이어진다. 인접 클립·대기 사이의 접점(자세·위치·가림 상태)을 맞추는 원칙을 ThrowSnow에서 참고한다. 눈덩이·명중·쌓임 같은 ThrowSnow 전용 동작은 없다.
- fps, 파일 형식, 알파/크로마키 처리, 클립 간 전환 방식, 불러오기 실패 시 대체 표시(fallback)는 소스를 받아 본 뒤 정한다. — 미정
- 재생 계층은 불러오기·재생을 취소 가능하게 하고, 실패·폐기 때 쓰던 자원을 정리한다(ThrowSnow `seq-media.js` 방식 참고). — 제안

## 8. 설정과 진단 — 제안

- 센서 수치(임계값, 유지 시간, stale 시간, `no-target` 처리)와 미디어 설정(소스 경로, 클립 구성, 타임아웃)은 설정 한 곳(`public/display/config/`)에 둔다.
- 최소 진단 표시: 입력 `source`, 최근 샘플과 상태·경과 시간, 안정화된 근접 판정, 현재 시퀀스 상태, 재생 ID·재생 상태, 최근 오류.
- 진단 표시는 운영 화면에서 기본으로 숨기고, 키나 URL 인자로 켠다.

## 9. 검증 구분

- 모의 입력으로 확인한 동작, 실제 센서로 확인한 동작, 현장에서 확인한 동작을 구분해 기록한다.
- 근접 판정·시퀀스 상태는 순수 모듈이라 시각을 넣어 작게 검증할 수 있다. 센서·현장 수치는 실측 전까지 미검증으로 둔다.
