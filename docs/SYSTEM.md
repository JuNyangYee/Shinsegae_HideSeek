# 기술 명세

기술 규칙을 담는다. 체험 기획·범위는 [PROJECT.md](PROJECT.md), 작업 경위와 인계는 [logs/](logs/)의 최신 로그를 따른다.

- 상태(2026-10-21): **세로 9:16 실제 시퀀스 영상 + 유화 후처리 + 모의 근접 입력이 구현되어 있다.** 모의 입력 → 근접 판정 → 시퀀스 상태 → 영상 재생기 → 무대 렌더러(유화)가 연결되어 동작한다. 실제 센서 어댑터·로컬 브리지는 **미구현**이다.
- 표기는 PROJECT와 같다: **확정** / **제안** / **가정** / **임시 선택** / **미정**. 거리 0.6 / 1.2 m는 **기획값**(v02 스토리보드), 그 밖의 판정·재생 수치는 **임시값**이다(9장). 유화 필터 값은 **ThrowSnow 운영값**이다.

## 1. 구성과 기술 선택

- 단일 PC에서 로컬 서버와 표시 페이지(브라우저)를 함께 실행하는 하드웨어 체험 앱이다. 배포·DB·WebSocket 없음. — 확정(범위)
- Node.js 24, 빌드 없는 ES module. 런타임 의존성은 `three` **0.186.1 고정**(ThrowSnow와 같은 판) 하나뿐이다. — 2단계 구현
- 브라우저: WebGL2 필요(Three.js 0.186). WebGL2를 못 쓰면 화면에 한국어 오류를 보이고 안전 정지한다(7.4절).
- 서버(`server/`): Node 내장 `http`.
  - `server/server.js` — 실행 진입점. `127.0.0.1`에만 bind. `PORT`(기본 8091, `0`이면 빈 포트 자동 선택). 잘못된 `PORT`·사용 중 포트·권한 오류는 한국어 문구 후 종료 코드 1. 미디어 폴더·three가 없으면 시작 때 경고.
  - `server/app.js` — 요청 처리(listen하지 않음, 테스트가 import). GET/HEAD만(그 외 405), `/` → `/display/` 302, 폴더 주소는 끝 `/`로 301 후 `index.html`.
  - `server/media.js` — 미디어 allowlist·Range(8장).
- 브라우저가 mmWave 센서를 직접 읽을 수 있다고 가정하지 않는다. 센서 인터페이스가 정해진 뒤 브라우저 API로 가능한지, 로컬 브리지가 필요한지 정한다. — 미정

## 2. 경계와 데이터 흐름

```text
[모의 입력 어댑터 | (미구현) 센서 어댑터] → 공통 근접 샘플 → 근접 판정(순수) → 시퀀스 상태(순수) → 영상 재생기 → 무대 렌더러(유화)
```

| 구성 요소 | 파일 | 맡는 일 | 맡지 않는 일 |
|---|---|---|---|
| 입력 어댑터 | `input/mock-input.js` | 선택된 거리·상태를 일정 간격의 공통 근접 샘플로 내보낸다. | 판정, 연출 |
| 모의 조작부 | `input/mock-controls.js` | 슬라이더·버튼·단축키를 어댑터 호출로 바꾼다(개발용). O·D 키는 콜백으로 넘긴다. | 판정·시퀀스 코어 직접 호출 |
| 근접 판정 | `core/proximity.js` | 샘플을 안정화된 `far`/`mid`/`near`/`unknown`으로 바꾼다(5장). | 장치 형식, 재생 |
| 시퀀스 상태 | `core/sequence.js` | 판정과 재생 완료·오류·일시 중지로 단계를 바꾸고 재생 지시를 낸다(6장). | DOM, 타이머, 영상 요소 |
| 영상 재생기 | `scene/seq-player.js` | 지시받은 클립을 `<video>`로 편집 구간(in/out)만 재생하고 완료(out 도달·`ended`)·오류를 재생 ID와 함께 알린다. 지금 보여야 할 요소(`display`)를 정한다. | 단계 결정, 그리기 |

- 근접 판정과 시퀀스 상태는 현재 시각 `nowMs`를 인자로 받는 순수 모듈이다(DOM·타이머 없음). 실제 센서 어댑터도 같은 샘플 규격으로 같은 경로를 타게 한다.
- 판정이 **바뀔 때만** 시퀀스 상태에 전달한다.

## 4. 공통 근접 샘플

| 필드 | 의미 |
|---|---|
| `source` | 입력 출처(현재 `mock`, 이후 예: `mmwave`). 빈 문자열 불가 |
| `timestampMs` | 샘플을 받은 시각. 페이지 단조 시계 `performance.now()` 기준 ms, 0 이상 유한수 |
| `status` | `ok`(대상 감지, 거리 있음) / `no-target`(장치는 정상, 감지 대상 없음) / `error`(장치 오류·연결 끊김·형식 오류) |
| `distanceM` | `status`가 `ok`일 때만. 센서 기준 대상까지 거리, 0 이상 유한수, 미터 |

- `no-target`(정상 무감지)은 **원거리 구역 샘플**이다(v02 "입력 없음 = 기본 놀이"). `error`·stale(샘플 끊김)은 `unknown`이다. 두 경우를 섞지 않는다. — 임시 선택
- 여러 사람 감지 시 대표 거리 선택, 정지한 사람 감지 특성, 거리 대신 존재 여부·구역만 주는 장치 대응은 센서가 정해진 뒤 정한다. — 미정

## 5. 근접 판정

출력: `far` / `mid` / `near` / `unknown`. 최초는 `unknown`.

- **구역(기획값):** 거리 `< nearBelowM(0.6)` → near, `0.6 ≤ 거리 ≤ farAboveM(1.2)` → mid, `> 1.2` → far. 경계값 0.6 m와 1.2 m는 **mid**다. `no-target`은 far.
- **노이즈 여유(임시값 `retreatMarginM` 0.05 m):** 지금 판정보다 **멀어지는 쪽으로만** 경계를 넓힌다. 다가갈 때는 기획값 그대로.
  - near → 바깥 후보는 거리 ≥ 0.65 m부터. mid·near → far 후보는 거리 > 1.25 m부터.
  - far·unknown에서는 여유 없이 기획값으로 나눈다.
  - 생성 조건: `nearBelowM + retreatMarginM < farAboveM`. 아니면 오류.
- **연속 유지(임시값):** 지금 판정과 다른 구역 샘플이 샘플 시각 기준으로 끊김 없이 이어져야 바뀐다. 더 가까운 구역이면 `approachHoldMs`(350 ms), 더 먼 구역(감지 없음 포함)이거나 `unknown`에서 회복할 때는 `retreatHoldMs`(600 ms). 유지 중 다른 구역·지금 판정과 같은 구역·거절된 샘플이 오면 후보가 끊기고 다음 샘플부터 새로 센다.
- **신호 공백:** 후보 유지 중 샘플 간격이 `maxSampleGapMs`(300 ms)를 넘으면 공백을 세지 않고 새로 센다. 직전 정상 샘플과의 간격이 `staleMs`(1200 ms)를 넘으면(주기 확인이 늦었어도) 먼저 `unknown`으로 바꾼 뒤 그 샘플부터 다시 판정한다.
- **샘플 거절:** 규격 위반(필드·상태·거리 형식, 음수 거리), 현재 시각보다 미래, `staleMs`보다 오래됨, 직전 정상 샘플보다 이른 시각(역행)은 판정에 쓰지 않고 진행 중 후보도 끊는다. 거절만 계속되면 stale이 된다. 최근 거절 사유는 진단에 보인다.
- **`error`·stale:** 즉시 `unknown`, 후보 초기화. 회복 후 유지 시간(600 ms)을 처음부터 채워야 한다. stale은 주기 확인(`tick(nowMs)`)에서 마지막 정상 샘플 후 `staleMs` 초과 시 정한다.
- 판정이 바뀐 호출에서만 `changed: true`를 돌려준다.

## 6. 시퀀스 상태

단계(phase)와 영상:

| 단계 | 영상 | 시작→끝 자세 | 성격 |
|---|---|---|---|
| `safe` | H 정지 이미지(`H_Hidden.png`) | H | 안전 정지(시작·unknown·재생 오류 대기·일시 중지) |
| `play` | far: SC0A → SC0B → SC0C 순환 / mid: 중간 대기 순환(`midIdleCycle`) | P→P | 반복 |
| `notice` | SC1_Notice | P→P | 1회(near·far면 연결 구간에서 전환) |
| `duck` | SC2_Duck | P→H | 1회(끊지 않음 — 숨는 동작 보호) |
| `hidden` | 숨은 대기(클립 없음, 자동 재생 없음) | H | mid·far가 되면 바로 `return` |
| `return` | SC4_Return_To_Play | H→P | 1회(near면 바로 `rehide`로 반전, mid·far는 그대로) |
| `rehide` | SC4R_Rehide = SC4 역방향 파생 영상 `SC4_Return_To_Play_Reverse.mp4` | 지금 자세→H | 1회(mid·far면 바로 `return`으로 반전, 끝나면 숨은 대기) |

- **중간 대기:** SC1b_Glance가 없어(`clips.SC1b_Glance.file = null`) `midIdleCycle = playCycle`(SC0A/B/C)로 대체한다. 영상이 생기면 `settings.js`의 `SC1b_Glance.file`·`durationMs`와 `server/media.js` allowlist에 추가하면 `midIdleCycle = ['SC1b_Glance']`가 된다. 순환 위치는 far용·mid용을 따로 기억한다.
- **숨은 대기(사용자 요청 2026-10-21 — 너구리 빼꼼 폐지):** `duck`·`rehide`가 끝났거나 안전 정지에서 시작할 때 판정이 near면 클립 없이 `hidden`에 들어가고, **자동으로 재생하는 클립·타이머가 없다.** 시간이 지나도 그대로이고 mid·far가 되면 바로 `return`한다. SC3_Hidden_Clue는 실행 클립 표에서 빠져 불러오지도 재생하지도 않는다(원본 파일과 서버 주소는 미사용 자료로 보존). 앞선 "8~16초 랜덤 뒤 SC3 1회"(`hiddenClueDelayMs`·`clueAtMs`·주입 `random`)는 폐지했다.
- **숨은 대기 화면:** 새 지시를 내지 않는다. 재생기는 직전 `duck`·`rehide` 영상의 **마지막 프레임**(안전 정지에서 시작했으면 H 정지 이미지)을 그대로 보인다. 같은 프레임이라 연결이 튀지 않고, 별도 이미지로 바꾸지 않는다.
- **눈치챔 기억(`noticed`):** 판정이 far가 아닌 동안 이미 관객을 알아챘는가. `notice`·`duck`·`hidden`·`return`을 시작할 때(판정이 far가 아니면) 켜지고, 판정이 **far로 바뀌면** 꺼진다. 같은 mid에 머무르면 눈치챔을 반복하지 않고, far로 갔다가 다시 mid에 오면 다시 눈치챈다.

**판정 변화와 클립(사용자 요청·정정 2026-10-21):** 끊겨 보이지 않게 하되, 모든 클립을 끝까지 기다리지는 않아 거리 반응이 늦어지지 않게 한다(직전의 "모든 클립 완주" 정책은 사용자가 반응이 너무 늦다고 정정해 폐지 — 확정 요구). 판정은 마지막 하나만 저장한다.

- **자세 연결 구간(사용자 요청 2026-10-21 — "고정시간으로 끊지 말고 적정 시간에 교체", 앞선 "판정 + 0.8초 강제 전환" 대체):** 놀이·눈치챔 중에 다른 클립이 필요한 판정이 오면 **연결 대기**(`pending`, 목적 하나: `duck`·`notice`·`play`)를 두고 재생기에 `cueWatch`로 목적을 알린다. 재생기가 그 클립의 실제 영상 위치(`currentTime`)가 연결 구간(`clips[].cues`) 안에 들어온 것을 알리면(`cueReached`) 현재 재생 ID·대기·목적이 아직 맞을 때만 그 자리에서 최신 판정의 다음 클립으로 잇는다. **벽시계 시간만으로는 절대 끊지 않는다.** 구간이 없거나 다 지나면 정상 완료(out)에서 최신 판정으로 잇는다. 판정이 되돌아오면 대기를 취소(`cueWatch` target null)하고, 목적이 바뀌면(예: near → mid) 새 목적을 알린다. 늦은·이전 재생·목적이 바뀐 알림은 무시하고 센다(`ignoredCues`). 거리 요청이 없으면 구간에서 자르지 않는다(놀이 A/B/C 순환은 in/out 그대로).
- 연결 구간(임시 연출값 — 오케스트레이터가 원본을 0.25초 간격·후보 양끝 0.125초로 네 캐릭터를 함께 눈으로 비교. 자동 자세 인식이나 완전히 같은 자세가 아니다. 도착 자세(SC2 0초·SC1 1.5초·놀이 시작의 눈사람 쪽 기본 자세)가 모두 같은 기본 놀이 계열이라 목적별 구분은 없다):

| 출발 클립 | 연결 구간(원본 초, 양끝 포함) | 근거(오케스트레이터 시각 판단) |
|---|---|---|
| SC0A_Pat | 0.25~0.375, 2.375~2.625, 4.125~4.25, 6.5~7.25 | 초반 기본 자세, 손 내려놓는 박자 2회(몸 방향 유지 — 여우 팔이 기본보다 조금 높음), 말미 기본 자세 복귀 |
| SC0B_Roll | 0.5~0.75, 6.75~8.0 | 초반 기본 자세, 굴리기를 마치고 몸·손·시선이 돌아온 뒤(2.5~5.5초 전면 자세·너구리 이동은 제외) |
| SC0C_Playful | 0~0.5, 1.5~1.875, 7.5~7.75 | 초기 동작, 몸을 크게 돌리기 전 손을 둔 구간, 말미 기본 자세 복귀(2.5~6.5초 제외) |
| SC1_Notice | 1.5~2.75, 6.25~6.75 | 고개를 크게 들어 관객 쪽을 보기 전, 눈사람 쪽으로 돌아온 뒤 |

- **한계:** SC0B는 중간 호환 자세가 없어 큰 동작 직후 요청이면 6.75초까지(1배속 최대 약 6초), SC0C는 최대 약 5.6초 기다릴 수 있다(근접 판정 유지 시간·불러오기 제외). 좁은 구간을 이벤트 지연으로 통째로 놓치면 다음 구간이나 정상 끝까지 간다. 모든 요청에 짧은 반응을 보장하지 않는다.
- **섞기:** 다른 영상으로 넘어갈 때(클립 끝·연결 구간) 이전 화면(멈춘 마지막 프레임)과 새 영상을 `naturalBlendMs` 150 ms(임시값) 섞는다. 새 영상은 섞는 동안에도 재생되므로 정지 시간이 늘지 않는다(7.3절). 다른 자세를 감추는 용도가 아니다. 안전 정지(H)·H 이미지에서 시작·같은 영상 재시작·복귀 정/역 반전은 섞지 않는다.

| 지금 상태 | 새 판정·사유 | 동작 |
|---|---|---|
| 어느 단계든 | unknown(입력 오류·stale), 재생 오류·timeout, 일시 중지(탭 숨김·그리기 불가) | 바로 끊고 `safe`(H 정지 이미지, 섞지 않음). 연결 대기 취소. 현재 재생의 오류는 다른 처리보다 먼저 |
| `play` | near, 또는 mid(눈치챔 전) | 연결 대기 → 연결 구간에서(없으면 정상 끝에서) `duck` / `notice` |
| `notice` | near, far | 연결 대기 → 연결 구간에서(없으면 정상 끝에서) `duck` / `play` |
| `return` | near | **대기 없이 바로 `rehide`**(정/역 반전, 아래). mid·far는 이미 나오는 방향이라 그대로 |
| `rehide` | mid·far | **대기 없이 바로 `return`**(정/역 반전). near는 그대로 |
| `hidden` 숨은 대기(클립 없음) | mid·far | 끊을 클립이 없으므로 바로 `return` |
| `duck` | 어느 판정이든 | 대기하지 않음. 놀라서 숨는 동작(편집 0~3.5초)을 마친 뒤 최신 판정으로 |

클립이 끝났을 때, 연결 구간에서 이을 때(또는 클립 없는 상태에서 판정이 바뀌었을 때) 다음:

| 끝난·끊긴 단계(또는 `safe`에서 시작) | 판정 near | 판정 mid | 판정 far |
|---|---|---|---|
| `safe`·`duck`·`hidden`·`rehide` (H 쪽) | `hidden` 숨은 대기 | `return` | `return` |
| `play`·`notice`·`return` (P 쪽) | `duck` | 눈치챔 전이면 `notice`, 아니면 `play`(중간 대기) | `play`(기본 놀이) |

- **자세(H/P) 연결:** 놀이·눈치챔(P→P)은 연결 구간(기본 놀이 자세)에서 `duck`(P→H)·`notice`·`play`로 잇는다. 복귀 SC4 중 near는 SC2로 건너뛰지 않고 정/역 반전(아래)으로 지금 자세에서 되돌아 숨는다. 숨기 SC2는 끊지 않는다(P→H 도중에 끊으면 엉뚱한 중간 자세로 튐).
- **복귀 정/역 반전(사용자 요청 2026-10-21, 확정 요구 — 앞선 "역재생 안 함" 대체):** `return` 중 near → `rehide`(SC4 역방향 파생 영상), `rehide` 중 mid·far → `return`. 판정 안정화(350/600 ms)는 그대로이고, 그 뒤 **연결 대기 없이 바로** 바꾼다. 지시에 `mirror: true`, `blendMs` 0(섞지 않음)을 싣고, 재생기가 **요청 순간 실제로 보이는 프레임**의 대응 지점부터 시작한다(7.1절). 처음·끝으로 되돌리지 않는다. 새 영상이 준비될 때까지 이전 프레임을 유지한다. `rehide`가 끝(모두 숨음)에 닿으면 near면 숨은 대기(자동 재생 없음), mid·far면 일반 `return`(편집 시작점부터). 다 나와 `play`가 된 뒤의 near는 연결 대기 → `duck`. 반전 재생의 timeout은 시작 지점을 코어가 모르므로 편집 구간 전체 길이(남은 구간의 상한) + 여유로 잡는다. 역방향 파일 누락·손상은 일반 재생 오류(즉시 H 안전 정지 → 재시도)이며 SC2로 대신하지 않는다.
- 예: 놀이 중 near → far로 연결 구간 전에 되돌아오면 대기가 취소되고 놀이를 이어 간다. 숨는 중 far → mid → far면 숨기를 끝낸 뒤 far로 `return`. 복귀 중 near가 안정되면 바로 그 자세에서 거꾸로 숨고(`rehide`), 그 도중 다시 far면 바로 그 자세에서 나온다(`return`).
- 이전 규칙 중 폐지: 즉시 끊기(`interruptPlayForNotice` 등, 첫 단계), 모든 클립 완주 대기(두 번째 단계), 판정 + 0.8초 강제 전환과 200 ms 강제 섞기(`switchWithinMs`·`forcedBlendMs`, 세 번째 단계 — 자세 연결 구간으로 대체), 복귀 중 near → SC2 강제 전환(정/역 반전으로 대체).
- **시작:** `safe` + `unknown`. 유효 판정이 처음 생기면 위 표대로(near → `hidden` 숨은 대기, mid·far → `return` → 놀이). unknown·일시 중지에서 회복할 때도 같다. unknown을 far로 보지 않는다.
- **재생 ID:** 클립을 시작할 때마다 새 ID(1부터 증가, 반복 루프도 회차마다 새 ID). 완료·오류 알림은 현재 ID일 때만 받는다. 늦은·중복·취소된 알림은 무시하고 진단에 센다.
- **timeout:** 클립 시작 시각 + **편집 구간 길이**(`clipPlayMs` = `outSec − inSec`, 편집 없으면 원본 `durationMs`) + `playTimeoutMarginMs`(4000 ms, 불러오기·탐색 포함)를 넘기면 재생 오류(`timeout`). 기한을 넘겨 도착한 완료도 timeout이다. 길이 타이머로 성공 처리하지 않는다.
- **재생 오류:** 재생기 오류(불러오기·탐색·`play()` 실패, 자동 재생 막힘)와 timeout은 `safe`로 바꾸고 `playbackRetryDelayMs`(3000 ms) 뒤 최신 판정으로 다시 시작한다. `retryNow`는 대기를 건너뛴다(자동 재생 막힘을 사용자 조작으로 푼 직후).
- **일시 중지(`setSuspended`):** 탭 숨김, 그리기 불가(렌더러 생성 실패·직접 그리기 실패) 동안 `safe`로 두고 판정이 바뀌어도 재생하지 않는다. 풀리면 최신 판정으로 다시 시작한다. 영상이 보이지 않는 곳에서 혼자 진행하지 않게 한다.

## 7. 영상 재생과 유화 후처리

### 7.1. 재생기(`scene/seq-player.js`)

- 클립마다 `<video>` 하나(음소거·playsinline·preload auto·loop 없음)를 시작할 때 미리 만든다. 주소는 `/media/seq/<file>`(서버 Range로 탐색).
- **편집 구간(in/out, 2026-10-21 사용자 정정에 따른 요구):** 사용자가 말한 IDLE 연결의 "약 1초 멈춤"은 렌더러 정지가 아니라 **영상 처음·끝의 비슷한 자세 유지가 경계마다 겹치는 편집 호흡**이다(사용자 정정, 확정). 원본 MP4는 그대로 두고 재생할 때 `clips[].inSec`~`outSec`(초, 원본 기준)만 쓴다. 값은 오케스트레이터가 원본 프레임과 경계 프레임 쌍을 보고 정한 **임시 편집값**이다(9장 표).
- `play`: 준비 대기(`readyState ≥ 2`이고 탐색 중이 아님 — `loadeddata`·`seeked`·`canplay` 때 다시 확인) → `inSec`이 아니면 `inSec`으로 탐색(`seeked`) → `play()`. 모든 단계는 재생 토큰을 확인한다. 실제 재생이 시작된 뒤에야 `display`를 새 영상으로 바꾼다. 그 전에는 **이전 화면(멈춘 마지막 프레임 또는 H 이미지)을 유지**한다.
- **완료:** 실제 영상 시각(`currentTime`)이 `outSec`에 닿으면 그 프레임에서 멈추고 완료로 알린다. `outSec`이 없으면 `ended`. 확인은 `timeupdate`와, 재생 시작 때 남은 영상 시간만큼 뒤에 한 번 실제 시각을 확인하는 타이머(아직이면 남은 시간으로 다시 잼)로 한다 — 길이만으로 성공 처리하지 않고, 렌더 주기·별도 고빈도 루프를 쓰지 않는다. 완료 알림은 재생마다 한 번(이후 `timeupdate`·`ended` 무시). 재생 속도 1(24fps 원본 시간), 늘리기·정지 이미지 애니메이션 없음.
- **정/역 짝 시작 지점(`mirror`):** 클립 표의 `mirrorOf`·`frames`·`fps`·`hiddenSec`로 짝(SC4 ↔ SC4R)을 안다. `play`에 `mirror: true`가 오면 취소·되감기 전에, 지금 보이는 것(`display`)으로 시작 지점을 정한다 — 짝 영상이면 보이는 프레임 i의 대응 프레임 (frames − 1 − i)(`mirrorStartSec`, 프레임 가운데 시각, 길이 − t가 아님), 같은 영상이면(짝이 아직 화면에 나오기 전 되반전) 그 프레임, 둘 다 아니면 보이는 것이 숨은 자세이므로 `hiddenSec`. 편집 구간 안(끝 한 프레임 전까지)으로 자른다. 요청됐지만 아직 준비 중인 영상은 기준으로 쓰지 않는다. 준비 대기 중 미리 감기 탐색이 진행 중이면 그것이 끝난 뒤 시작 지점으로 탐색한다. out 완료·취소 뒤 늦은 콜백 무시·되감기 보호는 일반 재생과 같다.
- **자세 연결 구간 감시(`watchCues(playId, target)`, 2026-10-21):** 코어가 목적을 주면 **재생이 실제로 시작된 뒤에만**(준비·탐색 중 제외 — 로딩 시간·탐색 전 위치로 판단하지 않음) 그 영상의 `currentTime`이 목적에 맞는 연결 구간 안일 때 `onCue(playId, target, via)`로 알린다(구간마다 한 번, `via` = 클립·실제 위치·구간). 시작 전에 대기가 오면 첫 실제 위치부터 본다. 확인은 `timeupdate`와, 다음 구간 시작까지 남은 영상 시간만큼의 한 번짜리 타이머(아직이면 다시 잼)로 한다. 영상 시각이 지난 확인과 같으면(멈춤·버퍼링) 250 ms 간격으로만 다시 본다. 늦게 확인해 구간을 통째로 지났으면 그 구간을 건너뛴다(지나간 구간으로 자르지 않음). 목적이 바뀌면 구간을 처음부터 다시 보고, target null·취소·교체 뒤의 확인은 토큰으로 막는다. 전환 여부는 코어가 다시 검증한다. 렌더 주기·전역 고빈도 루프는 쓰지 않는다.
- **섞기 정보:** `play`에 `blendMs > 0`이 오고 지금 보이는 것이 다른 영상이면, 새 영상 표시 때 `display.blendFrom`(멈춘 이전 영상)·`blendMs`를 실어 렌더러가 섞게 한다(7.3절). 같은 영상 재시작·H 이미지에서는 섞지 않는다.
- **전환 대기 줄이기(2026-10-21):** `display`가 바뀌면 `onDisplayChange`로 바로 알리고, 조립부가 렌더러 `refresh()`를 불러 다음 화면 갱신(rAF)을 기다리지 않고 첫 그림을 그린다. 그 뒤 **지금 쓰지 않는 영상을 미리 `inSec`으로 되감는다**(`rewindIdle` — 다음 재생 때 탐색 대기 제거). 처음 불러온 영상도 `loadedmetadata` 때 `inSec`으로 미리 감는다. 표시 중인 요소, 현재 재생 요소, 렌더러가 아직 쓰는 요소(`isShown` = 렌더러 `usesElement` — 그리는 중·섞는 중), 불러오는 중·탐색 중·오류 요소는 건드리지 않는다. 미리 되감는 중에 그 영상이 재생 차례가 되면 탐색이 끝나기를 기다렸다 시작하고 다시 탐색하지 않는다. 표시 중인 같은 영상을 다시 재생할 때(예: 취소 뒤 같은 클립)만 재생 시작 때 탐색한다 — 이때 탐색이 끝나며 시작 프레임이 먼저 보일 수 있다. 2버퍼는 쓰지 않는다.
- **전환 계측(진단):** 최근 6개 재생마다 이전 클립 끝(out 도달·`ended`) → 재생 요청 → 준비(되감기 대기·탐색 여부) → 재생 시작(표시 교체) → 첫 영상 프레임(`requestVideoFrameCallback`이 있으면, 현재 재생일 때만 기록) 시각과 연결 구간(어느 구간의 몇 초에서 이었는지)·섞기 여부·완료 방식(out/ended)을 남긴다. 렌더러는 마지막 표시 교체 시각과 그 뒤 첫 그림 시각을 남긴다. 개발 패널 '최근 전환' 행에만 보인다(운영 화면 표시 없음). 이 값은 앱의 재생·그리기 호출 시각이며, 사용자가 말한 멈춤(편집 호흡)이 사라졌다는 증거가 아니다 — 편집 호흡은 영상 내용 문제라 실제 화면을 보고 판단한다.
- `cancel`·교체: 영상을 멈추고(그 프레임 유지) 리스너·out 확인 타이머를 뗀다. 취소·교체된 재생의 `play()`가 늦게 끝나면 그 영상을 멈춘다(지금 재생이 같은 요소면 그대로).
- 오류: 준비·탐색 중 `error`, `play()` 거절(NotAllowedError → `autoplay-blocked`, 그 밖 → `play-failed:<name>`), 재생 중 `error`. 오류 난 요소는 다음 재생 때 새로 만든다(재시도 = 다시 불러오기).
- `setPose('hidden')`: 진행 중 재생 취소, 모든 영상 멈춤, `display` = H 이미지(`/media/pose/H_Hidden.png`).
- 안전 정지 이미지: 시작할 때 불러오고, 실패하면 3000 ms마다 새 `<img>`로 다시 불러온다(시도마다 세대 번호 — 이전 시도의 늦은 load·error 무시). 상태는 `stillStatus`(`loading`/`ready`/`error`).
- 정리: `dispose()`는 영상 `src` 해제·`load()`, 이미지 해제. 페이지를 떠날 때(`pagehide`, 뒤로 가기 캐시 제외) 부른다.

### 7.4. 그리기 경로와 실패 정책

- 경로 시험(생성·크기 변경·유화 다시 켬·단계 구성 변경 때): 운영 그리기 함수를 그대로 불러 GL 오류로 시험한다 — 후처리 반정밀(확장 있을 때) → 후처리 8비트 → 직접 그리기.
- 경로 선택: 유화 켬 + 후처리 가능 → 유화. 아니면 직접 그리기(원본). 직접이 안 되고 후처리만 되면 후처리 강제.
- **유화 실패 → 원본 대체 + 오류 표시:** 유화를 켰는데 후처리 시험 실패, 실행 중 예외, 첫 획 층 칠함 확인(WebGL2 질의, 유화를 켠 뒤 결과 기준) 실패면 직접 그리기(원본)로 바꾸고 무대 위쪽에 빨간 띠로 "유화 필터 오류 — 원본으로 표시 중"과 사유를 보인다(콘솔 오류도). 조용히 성공으로 보고하지 않는다. **O로 껐다 켜면 실패를 지우고 새로 시험**한다.
- **그리기 불가(공통 복구 상태):** 고를 수 있는 경로가 하나도 없으면 — WebGL2·렌더러 생성 실패, 경로 시험에서 모두 실패, 직접 그리기 예외, 또는 원본(직접) 경로가 없는 상태에서 유화 실패 — 무대 가운데에 한국어 오류("화면을 그릴 수 없습니다…")를 보이고 시퀀스를 일시 중지(안전 정지)한다. 실행 중에는 `recoverRetryMs`(1000 ms)마다 다시 시험하고, **실제로 고를 경로가 생겼을 때만** 풀린다. 원본 경로가 생기면 유화 실패는 그대로 두고 원본 대체·경고를 유지한다(유화 재시도는 O). 원본 경로가 없고 후처리 시험만 통과하면 유화 실패를 지우고 후처리로 다시 시도한다(칠함 확인은 그 뒤 결과로 다시 판단). 렌더러 생성 실패는 새로고침해야 한다.
- **안전 정지 화면 미준비:** 안전 정지를 요청했는데 H 이미지가 아직 불러오는 중이거나 실패했으면, 이전 영상 프레임(캐릭터가 보이는 화면)을 남기지 않고 검정 가림 화면을 그린다. 실패 중이면 무대 가운데에 "안전 정지 화면(H 이미지)을 불러오지 못했습니다. 다시 시도하는 중입니다"를 보인다. 이미지가 준비되면 그 이미지로 바꾸고, 시퀀스는 이미지와 무관하게 정상 판정에 따라 진행한다. 다음 **영상** 전환은 기존대로 새 영상이 재생을 시작할 때까지 이전 프레임을 유지한다.
- 자동 재생이 막히면 무대 가운데에 "화면을 클릭하거나 아무 키나 누르면 재생을 시작합니다"를 보이고, 사용자 조작 때 `retryNow`로 바로 다시 시도한다.

- 개발 패널: 운영 화면에서는 **기본 숨김**. `?debug=1`로 열린 채 시작, `D` 키로 전환. 열면 무대 옆 칸(좁은 창은 아래)을 차지해 무대를 덮지 않는다. 맨 위에 "개발용 모의 입력 — 최종 센서 연동 아님" 표시.
- 단축키(물리 키 `event.code`, 한글 입력 상태에서도 동작): N 가까이 0.4 m, M 중간 0.9 m, F 멀리 1.6 m(프리셋 버튼·키는 입력 상태를 정상 감지로 돌림. 슬라이더는 거리 값만 바꾸고 감지 없음·입력 오류 상태를 유지), O 유화 켬·끔, D 패널. 입력 칸·슬라이더에 초점이 있거나 조합 키·키 반복이면 무시(체크박스 초점은 허용).
- 진단(패널이 열려 있을 때만 갱신): 입력 원본·보낸 샘플 수, 마지막 샘플·경과(stale), 근접 판정·후보 유지 시간, 단계·관객 인지 여부(`noticed` — 눈치챔 재생 완료가 아니라 이번 근접 방문에서 이미 알아챈 상태)·숨은 대기(자동 재생 없음) 표시·연결 대기(목적·경과·판정) 또는 마지막 연결 결과(연결 구간의 클립·실제 초·구간 / 정상 끝 / 취소)·일시 중지 사유, 재생 ID·무시한 늦은 알림 수·받지 않은 연결 알림 수, 재생기(진행 단계·현재 영상 시각/길이·편집 구간·연결 대기 목적과 가능 구간·readyState·마지막 결과), 화면 표시(H 이미지 / 영상 클립), 최근 전환(연결된 구간·실제 초·섞기 ms·완료 방식 out/ended, 이전 클립 끝 → 첫 그림 ms, 끝 → 요청, 요청 기준 준비·재생 시작·첫 영상 프레임·첫 그림, 최근 6개의 끝 → 재생 시작 ms), 그리기 경로·그림/s(설정값과 함께)·화면 갱신(rAF)/s·마지막 그림 시간(CPU 제출 시간)·캔버스 크기·경로 시험 결과, 유화(켬·적용·내부 크기·획 수·칠함 확인), 영상 소스별 상태(미리 되감기 횟수 포함), 참고(SC1b 대체·SC1 원본/편집 길이·편집 구간 임시값·모의 입력), 최근 오류.

## 10. 실행과 검증 구분

- 실행: `npm ci` 후 `npm start`(`http://127.0.0.1:8091/display/`), 테스트: `npm test`(`node --test`, `test/`의 근접 판정·시퀀스 상태·미디어 서버 시나리오, 재생기 미리 되감기·취소 경쟁은 가짜 media 요소로). 미디어 서버 테스트는 임시 포트로 테스트 안에서만 서버를 띄운다(규칙 시험은 임시 폴더의 가짜 파일, 기본 경로 시험은 저장소 실행 에셋을 다른 cwd에서 HEAD·Range로 확인).
- 모의 입력으로 확인한 동작, 실제 센서로 확인한 동작, 현장에서 확인한 동작을 구분해 기록한다. 현재는 **단위 테스트와(오케스트레이터의) 브라우저·HTTP 확인까지**이며 실제 센서·현장 수치·장시간 동작·설치 PC GPU 성능은 미검증이다. 검증 내역은 최신 로그를 따른다.
