# 프로젝트 기획과 작업 계획

체험 기획·범위·단계 계획을 담는다. 기술 규칙은 [SYSTEM.md](SYSTEM.md), 작업 경위와 인계는 [logs/](logs/)의 최신 로그를 따른다.

- 표기: **확정** = 사용자가 정한 요구 / **제안** = 이 문서가 내놓은 초안(사용자 확인 전) / **가정** = 진행을 위해 임시로 둔 전제 / **미정** = 사용자·하드웨어 결정이 필요한 사항.
- 현재 상태(2026-10-20): **문서만 있다. 실행 앱·코드·패키지는 아직 없다.**

---

## 1. 개요와 목표

- 웹 기반 숨바꼭질 체험이다. — 확정
- mmWave 센서로 관객이 가까워지면 캐릭터가 숨고, 멀어지면 다시 나온다. — 확정
- 미리 만든 영상/이미지 시퀀스를 상태에 맞춰 재생하는 시퀀스 기반 연출이다. — 확정
- 구조와 시퀀스 설계는 ThrowSnow 프로젝트와 비슷한 방향으로 한다(5장). — 확정
- 체험 의도: 관객이 다가가면 캐릭터가 몸을 숨기고, 물러서서 기다리면 슬며시 다시 나타나는 "다가가기 ↔ 물러서기"의 주고받음을 즐기게 한다. — 제안

## 2. 체험 흐름

기본 흐름(확정 요구를 순서로 정리):

```text
대기(캐릭터 보임) → 관객이 가까워짐 → 숨기 → 관객이 가까이 머무름 → 숨은 상태 유지
  → 관객이 멀어짐 → 등장 → 대기 → (반복)
```

- 가까이 머무는 동안에는 숨은 상태를 유지하고, 숨기 연출을 반복 재시작하지 않는다. — 제안
- 숨기·등장 도중 관객이 방향을 바꾸면 진행 중 연출을 마친 뒤 최신 상태로 다시 판단한다. — 제안(규칙은 [SYSTEM 6장](SYSTEM.md#6-시퀀스-상태))
- 시작 직후나 센서 상태를 알 수 없을 때 "멀어짐"으로 오인해 저절로 등장하지 않는다. — 제안

## 3. 범위

### 3.1. 이번 단계(부트스트랩)

- 포함: 작업 지침(AGENTS.md), 이 문서, SYSTEM.md 초안, 작업 로그, README 안내, 최소 `.gitignore`·`.gitattributes`, 사용자가 작업 중 제공한 비주얼 참고 이미지 보관(4.1절).
- 제외: 실행 코드, 패키지 설치, 빈 앱 폴더, 테스트 프레임워크, 웹 배포.

### 3.2. 확정되지 않은 체험 요소

- 점수·라운드·승패·보상·다중 인원 대응·소리·안내 문구는 **요구로 확정되지 않았다.** 자동으로 추가하지 않는다.
- 임시 진행 방식으로 **점수 없는 상시 반복형**(관객이 오가는 대로 숨기·등장을 반복)을 제안한다. — 제안, 사용자 확인 전

### 3.3. 가져오지 않는 것 (ThrowSnow 전용)

던지기 입력, 명중 판정, 눈 쌓임·녹음, 태블릿 조작·WebSocket, ThrowSnow의 전체 테스트 체계.

## 6. 단계별 작업 계획 — 제안

각 단계는 작은 작업 단위로 나누고, 단위마다 간단 검수를 거친다([AGENTS.md](../AGENTS.md)).

1. **모의 입력으로 흐름 확인:** 키보드 등 모의 입력 → 공통 근접 샘플 → 근접 판정 → 시퀀스 상태를 임시 화면(색 블록·자리표시 영상)으로 확인한다.
2. **영상 소스 연결:** 숨바꼭질 시퀀스가 제공되면 레이어·클립 구성과 재생 방식을 소스에 맞춰 정한다.
3. **실제 센서 연동:** 센서 모델·인터페이스가 정해지면 어댑터(필요 시 로컬 브리지)를 붙이고 판정 수치를 실측으로 정한다.
4. **현장 조정:** 설치 위치·관객 동선에서 임계값·유지 시간·연출 길이를 조정한다.
