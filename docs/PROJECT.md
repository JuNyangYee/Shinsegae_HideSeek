## 2. 체험 흐름 (v02 스토리)

출처: `D:/2026-09_ShinsegaeChristmas/007_Assets/Hide_Seek/HideSeek_Snowman_Play_v02/`의 README·SEQUENCE_PLAN·CONTINUITY_GUIDE·SESSION_HANDOFF와 사용자 스토리보드(`00_References/Storyboard/User_Storyboard_20261021.png`, 같은 그림이 2026-10-21 첨부로도 옴). 저장소에는 복사하지 않았다.

- 네 캐릭터(푸빌라·깨또·후트·포코)가 각자 눈 작품을 만들며 노는 장면(P)이 기본이다. 숨으면 모든 눈 작품은 그대로 남고 캐릭터만 가린다(H).
- 숨을 때는 놀던 자리 가까이(눈덩이·눈사람·우체통·눈더미 뒤)로 몸을 낮추고, 나올 때는 같은 자리에서 손을 다시 얹어 놀이를 잇는다. 중앙에 모이거나 일렬로 서지 않는다.

| 관객 위치(기획값) | 연출 | 영상(시작→끝) |
|---|---|---|
| 없음 / 1.2 m 밖 | 기본 놀이 A → B → C 순환 | SC0A_Pat · SC0B_Roll · SC0C_Playful (P→P) |
| 1.2 m 안으로 들어옴 | 놀다가 눈치챔 1회 | SC1_Notice (P→P) |

- 거리 0.6 / 1.2 m는 스토리보드의 기획값이다. 실측값이 아니며 센서 노이즈 여유·유지 시간은 구현 쪽 임시값이다([SYSTEM 5장](SYSTEM.md#5-근접-판정)).
- 24~30초 놀이 길이는 영상 소스 길이이며, 관객 입력에 그만큼 기다렸다 반응하라는 뜻이 아니다(v02 SEQUENCE_PLAN).
- **사용자 요청(2026-10-21):** 거리에 따라 영상이 뚝뚝 끊기는 것을 줄인다. — 확정 요구
- **사용자 정정(2026-10-21, 확정 요구):**
  - 모든 클립을 끝까지 기다리면 거리 반응이 너무 늦다. → 놀이·눈치챔·복귀·단서 중에 다른 클립이 필요한 판정이 오면 약 0.8초 안에 끝나면 자연스럽게 잇고, 아니면 짧게 섞어 바꾼다(전환 예약). 숨기는 숨는 동작을 마친다. 판정이 금방 되돌아오면 예약을 취소한다. 입력 오류·샘플 끊김·탭 숨김·그리기 불가는 즉시 안전 정지한다. 상세는 [SYSTEM 6장](SYSTEM.md#6-시퀀스-상태).
  - IDLE 연결의 "약 1초 멈춤"은 렌더러가 멈춘 것이 아니라 **영상 처음·끝의 비슷한 자세 유지가 경계마다 겹치는 편집 호흡**이다. → 원본 파일은 그대로 두고 클립별 재생 구간(in/out)으로 줄이고, 남는 손·머리의 미세한 차이는 경계에서 150 ms 섞는다.
- 수치(0.8초 예약, 섞기 150/200 ms, 클립별 in/out)는 **임시값**이다. in/out은 오케스트레이터가 원본 프레임과 경계 프레임 쌍을 보고 정했다(자동 검출 결과 아님).
- **사용자 요청(2026-10-21):** 다 숨은 뒤 단서(SC3)가 계속 반복되지 않게, 숨은 채 대기하다 가끔 한 번만 재생한다. SC3 4.04초 안에서 너구리(후트)가 오른쪽 우체통 옆에서 고개를 한 번 내밀었다가 끝에 다시 숨는다(오케스트레이터 프레임 확인) — SC3은 재생 구간도 편집하지 않는다.
