## 확정 요구와 구현 선택

- 사용자 확정 요구: 센서 없이 숫자 1/2/3으로 가까이/중간/멀리 테스트, 병합 및 배포.
- 오케스트레이터 구현 선택(사용자에게 안내한 세부 동작):
  - 1/2/3 = 기존 모의 프리셋 0.4/0.9/1.6 m. 숫자패드는 NumLock 켬 상태만.
  - 실센서 중이어도 숫자 키로 모의 입력 자동 전환. 판정에는 모의 입력만 사용하고 센서 연결·명령·설정은 바꾸지 않음. 복귀는 D 패널의 `실센서` 버튼.
  - 한 번 누르면 정상 감지 + 전송 지속. 감지 없음·입력 오류·전송 중단 중에도 그 거리로 재개. 이미 모의 입력이면 입력 모드를 다시 초기화하지 않음.
  - 프리셋을 먼저 정한 뒤 모의 입력 시작(첫 샘플이 이전 거리·오류가 아님).
  - N/M/F는 모의 입력일 때만(기존 정책 유지). D/O 보존. 편집 칸 초점·Ctrl/Alt/Meta/Shift 조합·키 반복·IME 조합 중에는 가로채지 않음. 패널이 닫혀 있어도 동작, 패널 자동 열기 없음.
  - 숫자는 고정 거리 프리셋 — 기본 경계(0.6/1.2 m)에서 near/mid/far, 패널에서 경계를 바꾸면 판정이 달라질 수 있음(동적 재계산은 범위 밖).
- 구현 선택:
  - 숫자패드 NumLock 판별은 `event.key`가 숫자인지로 한다(NumLock 꺼짐이면 `End`·`ArrowDown` 등이라 무시).
  - 같은 이유로 위 숫자 줄도 `event.key`가 숫자가 아니면 무시한다. 한글 입력(조합 중 아님)에서는 숫자가 그대로 와서 동작한다. 숫자 줄에 숫자가 아닌 글자가 오는 자판(예: AZERTY)에서는 동작하지 않는다(가정: 현장 PC는 한글/영문 기본 자판).
  - 실센서 → 모의 전환은 기존 `setInputMode('mock')`를 그대로 쓴다. 그래서 패널 버튼 전환과 똑같이 판정 초기화 → 안전 정지(H)에서 첫 모의 샘플로 다시 판정한다(근접 판정 유지 시간 규칙 그대로). 이미 모의 입력이면 이 초기화가 없다.
  - 실센서 중 `activate`가 연결되지 않은 경우(다른 호출부)에는 모의 상태를 건드리지 않고 무시한다.
